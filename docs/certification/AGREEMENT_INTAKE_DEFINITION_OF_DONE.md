# Definition of Done — Three-Path Agreement Intake

DONE means a buyer/provider can start with no contract, an informal artifact, or a formal document; review provenance-backed proposed terms; resolve ambiguity; create the same canonical AssuraPay Agreement; negotiate/accept through existing governed boundaries; and continue into the existing performance/evidence/verification/payment lifecycle.

DONE additionally requires production persistence and RLS, authenticated APIs, accessible product UI, idempotent conversion, failure atomicity, observability without sensitive content, and green full regression/certification gates.

NOT DONE: domain-only tests; docs-only route/UI contracts; mocked persistence presented as production; AI self-acceptance; direct intake-to-payment path; three separate agreement aggregates; or declaring live PostgreSQL/browser gates green without execution evidence.
