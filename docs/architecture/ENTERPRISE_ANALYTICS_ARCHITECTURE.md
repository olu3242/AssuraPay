# Enterprise Analytics Architecture

`@assurapay/enterprise-analytics` closes Wave 6 (Enterprise Intelligence, Engines 51–60) and, with it, **the full 60-engine catalog**. Like `packages/enterprise-intelligence` (Batch 11), every engine here is a governed read model or forecast layer — nothing writes to or reads from another package's store; every signal is supplied by the caller.

Financial & Payment Intelligence (56) mirrors the exact governed-forecast shape used by Engine 55 and Engine 16: forecasts can only be produced through a `FinancialForecastGateway`, confidence is validated on every call, and every forecast starts `NOT_REVIEWED`. Vendor & Customer Performance (57) scores either side of a relationship — `partyRole` is `VENDOR` or `CUSTOMER` — from the same metrics shape, keeping accountability genuinely two-sided rather than payer-only. Portfolio Analytics (58) is a rollup snapshot with a `trend` query returning every snapshot for a scope in recorded order, so a caller can chart at-risk/blocked/unpaid/disputed/retained value and counterparty concentration over time without this package computing or caching a derived trend itself. Renewal & Relationship Intelligence (59) requires both a bounded readiness score and a non-empty rationale for every recommended action — `RENEW`, `RENEGOTIATE`, `DO_NOT_RENEW` or `REVIEW_REQUIRED` — so no renewal recommendation can be silent about why.

**Engine 60 (AI Decision Support & Continuous Improvement) is the capstone AI-governance engine for the whole platform.** Every model used anywhere in AssuraPay is expected to be registered here (`ModelRegistration`), evaluated against a threshold (`EvaluationRecord`), and monitored for drift (`DriftAlert`) — a failed evaluation **automatically raises a drift alert**, with severity scaled to how far below threshold the score fell, so evaluation and drift are never disconnected concerns a team could forget to wire together. `Recommendation` is the only artifact resembling a "decision" this engine produces, and it is never auto-executed: it starts `PENDING`, and only an explicit human `decideRecommendation` call can accept or dismiss it — the same non-autonomy invariant already established for Engine 16's analysis findings and every forecast engine in Waves 5 and 6.

The in-memory `TrustPersistence` adapter and `deterministicFinancialForecastGateway` certify orchestration only. Live PostgreSQL RLS and a production `FinancialForecastGateway` backed by a governed model remain deployment gates, consistent with prior batches.
