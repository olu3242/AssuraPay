# Execution Orchestration Security

Every record is workspace-scoped and backed by RLS contracts. An execution workspace cannot assign work items until active and cannot submit while any work item remains open, and only one execution workspace may ever be open per milestone. Progress records reject any stage or completion-percent regression, and `FINANCIALLY_EARNED` progress is unreachable without a prior `ACCEPTED` record at full completion and a positive earned value — no code path can report earned value ahead of accepted, evidenced work. Evidence packages cannot be submitted with a mandatory requirement uncovered, and verification requires reviewer notes; the full chain of custody (submission and every review decision) is retained on the record rather than overwritten. The quality gate fails on any open critical defect, and a defect cannot be marked resolved without an assigned root cause.
